# S288 动力学测量记录（M2 / M6b / M7）

标定日期 2026-09-11 ｜ S288 ID 0 ｜ 12.0 V ｜ 空载自由轴、**机身在台面上未夹持**
舵机壳体 55–60 ℃ ｜ 主机 Linux 6.8 aarch64 ｜ 环路实测 6.1–6.4 kHz（每帧往返 0.16 ms）

工具：`bam_dynamics.py`（`delay` / `compliance` / `backlash` / `inertia` / `sine`），
原始逐帧数据在 `bam_data/M2_*`、`M7_*`、`M6b_*`（未压缩 CSV 已 gzip）。
摩擦模型（`bam_fit.py`）是这次惯量测量的前提：`J = (τ − F(v)) / α`，F(v) 已知。

## 一、M2 指令延迟：0.48 ms 传输 + 一阶力矩建立 τ=0.54 ms

方法：`kp=kd=0`，让**纯力矩前馈**在 +0.02 / −0.02 N·m 之间跳变。两个值都**低于破断力矩
0.0365 N·m，所以轴完全不动** —— 这样测到的纯粹是"命令到达并体现在舵机自己的力矩读数上"
的时间，不含任何机械响应。80 次跃变（40 轮 × 双向）全部原始点一起拟合：

```
y(t) = 0                      t < td
y(t) = A·(1 − exp(−(t−td)/τ))  t ≥ td
```

| 量 | 值 | 说明 |
|----|-----|------|
| 传输延迟 `td` | **0.48 ms** | 拟合最优值；SSE 在 10% 以内的区间 0.44–0.51 ms |
| 力矩建立时间常数 `τ` | **0.54 ms** | 一阶；对应 10–90% 上升 **1.19 ms** |
| 幅度 A | 37.55 counts = **42.3 mN·m** | 命令 40 mN·m，偏高 5.8%（与已知的标度偏置一致） |
| 拟合残差 rms | 2.26 counts | 反馈噪声约 1 count → 一阶模型成立 |
| 逐次"首次偏离" | 0.34 / 0.58 / 3.90 ms（min/中位/max） | 受主机调度抖动影响，故以拟合值为准 |

要点：

* **延迟和上升要分开报**。手册预期"S288 延迟 < 5 ms"，实测端到端只有 0.48 ms，而且其中
  一大部分是 USB-CDC + 主机调度 —— 换成 robotd 直接走 Jetson UART（6 Mbps）时会变。
* 反馈的力矩读数在 40 mN·m 阶跃上**跟随命令到 1.7 mN·m 以内**（另一次测量），
  所以"命令值 ≈ 实际值"这个假设在这次测量里是成立的。
* 一阶上升意味着 sim 里的执行器模型不能只加纯延迟，还需要一个 ~0.5 ms 的一阶惯性。

## 二、M6b 传动链柔度：极硬，不是编码器偏差的来源

方法：`kp=kd=0`，力矩从 0 → ±0.032 N·m 阶梯扫描（全部低于破断点，轴不转），
同时看两个编码器：转子端推出的输出角（`pos/RATIO`）与输出端 13 bit 编码器（`OutPos`）。

| τ_cmd | 转子端推出的输出角变化 | 输出端编码器变化 | 差值 |
|-------|----------------------|----------------|------|
| ≤ 0.024 N·m | ≤ 1.5e-5 rad | **< 1 count**（分辨率 0.044°） | 即测不出 |
| 0.028 N·m | +6.4e-4 rad | +7.7e-4 rad | 开始蠕动 |
| 0.032 N·m | +1.8e-3 rad | +3.9e-3 rad | 明显蠕动（0.004 rad / 0.25 s） |

结论：

1. **传动链刚度 ≥ 1600 N·m/rad（输出端）**，换算到转子端约 0.019 N·m/rad。
   也就是说在 0.024 N·m 以内**输出端编码器一动不动、只有转子侧的弹性卷绕**，
   卷绕量 1.5e-5 rad 是转子编码器分辨率（6.6e-7 rad）的 20 倍，测得到。
2. **所以前面第一版测到的 0.5–1.7° 偏差不是柔度**，而是回差（见第三节）。
3. **静摩擦在"慢速蠕动"下只有约 0.028–0.032 N·m**，而快速破断需要 0.0365 N·m
   —— 破断点本身是速度/时间相关的（经典的 stick-slip）。做 sim2real 时如果策略是慢速
   精细动作，会先遇到 0.03 这一档。

## 三、M7 回差：1.06°（手册"S288 无需 backlash 模型"的说法不成立）

方法：对 3 个位置，每个位置**分别从下方和上方逼近**，每次 1.8 s 稳定后取后半段均值，
比较转子端推出的输出角与输出端编码器的差。稳定时 `|v| = 0.00000 rad/s`（真停稳）。

| 目标 | 从下方逼近的差 | 从上方逼近的差 | 回差 |
|------|--------------|--------------|------|
| 0° | −1.854° | −0.803° | **1.052°** |
| +10° | −2.316° | −1.301° | **1.014°** |
| −10° | −1.947° | −0.846° | **1.101°** |

* **回差 = 1.056° = 0.0184 rad**（三个位置 0.0177–0.0192，一致性 ±0.06°）。
* 两次独立跑的结果 1.042° vs 1.056°，**重复性 0.014°**。
* 两个编码器之间还有一个**恒定偏置 −1.40° … −1.81°**（随位置变化 0.4°，
  含输出端 13 bit 编码器自身的非线性）：这一项是标定偏置，**只有回差那一项是 sim 里的
  backlash**，两者必须分开报。

**这与手册第三节"输出端 13 bit 编码器消除了反冲、因此不需要 backlash 模型"直接冲突。**
实测 1.06° 的输出端滞回对足式机器人不是小量（足端定位、关节零位都在这个尺度上），
建议在 MuJoCo 里给关节加 `frictionloss` 或显式 backlash —— 至少在策略做双向精细动作时。

## 四、M6b 惯量：**未测出**，需要先夹持机身

两条独立方法互相印证，但两者给出的都不是舵机的惯量：

| 方法 | 结果 | 备注 |
|------|------|------|
| 正弦法（0.25 rad @0.5 Hz，kp=20） | \|J\| < 1.0e-3 kg·m²（拟合 J = −5.6e-4，R²=−0.63） | τ 与 v 相关 **+0.67**、与 α 相关 **−0.03** |
| 力矩阶跃法（0.06/0.09/0.12 N·m，kp=kd=0） | J = **4.7e-4 kg·m²**（三个力矩水平 4.3–4.9e-4，极一致） | 6 个窗口/力矩 |

**为什么这两个数都不是惯量：**

* 若机身刚性固定，关节空间的等效惯量应为 `J_rotor·RATIO² + J_load`。即使转子惯量只有
  1.2e-6 kg·m²（小无刷转子的量级），反射到输出端也有 **0.1 kg·m²** —— 比实测大 **200 倍**。
* 反作用力矩 ≈ 输出端力矩（20–120 mN·m）。而**让轴动起来本身就需要 ≥ 摩擦力矩 25 mN·m**，
  所以任何运动都意味着反作用已经超过台面能抓住的量级 → **机身必然在滑转**。
* 佐证：转矩与速度强相关、与加速度无关 —— 移动这个轴所需的力矩几乎全是摩擦，
  看不到惯性项；测到的"惯量"里混的是机身自己的惯量 + 线缆拖拽，而这两样是台架属性，
  不是舵机参数（对同一个舵机换一种摆放就会变）。

**结论：机身自由时无法测出惯量，这是物理限制而非方法问题。**
需要把舵机刚性夹持（台钳/G 夹/铝型材支架，或测试时用手牢牢按住机身，约 20 秒）。
夹持后重跑：

```bash
python3 bam_dynamics.py inertia --taus 0.06,0.09,0.12 --secs 0.3
python3 bam_dynamics.py sine --amp 0.25 --freq 0.5 --secs 8 --kp 20 --kd 1.0
```

判据：夹持后 J 应当**上升两个数量级**（到 ~0.1 量级）。如果仍然是 5e-4，那说明转子惯量
远比 1.2e-6 小，该结论本身就是重要信息（值得再核对一次 RATIO 的用法）。
