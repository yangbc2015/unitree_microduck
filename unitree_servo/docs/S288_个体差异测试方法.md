# S288 个体差异测试方法（多颗舵机）

对象：手上陆续会有多颗宇树 S288。目标是用**同一套流程**给每一颗产出一份可比较的记录，
从而回答两个问题：**个体差异有多大？哪些参数必须每颗都测、哪些可以直接沿用？**

一条命令跑完一颗：

```bash
python3 bam_unit.py run --id 0 --label S288-03 --voltage 12.0 --ambient 24 \
    --psu "你的电源型号" --operator 你的名字
python3 bam_unit.py compare          # 全部单元横向对比 + 重复性
```

工具与本文档是同一套：`run` 调用的就是你下面看到的那些命令，读数从每个命令的
`@@RESULT@@` 行回收，**不解析散文输出**，所以文档和工具不会各说一套。

---

## 一、先立规矩：不知道"噪声地板"，就没有"个体差异"

这是整套方法里最容易做错、也最贵的一步。

**同一颗舵机连测两遍的差 = 噪声地板。小于它的差不是个体差异。**

```bash
python3 bam_unit.py run --id 0 --label S288-01 ...      # 第一遍
python3 bam_unit.py run --id 0 --label S288-01-r2 ...   # 第二遍（背靠背）
```

`compare` 会把 `-rN` 后缀识别为**同一颗的重复**，单独列出每个量的重复差。
在那张表之前，任何跨单元散布都没有意义。

**两个必须记录的混淆项**（协议会自动写进每条记录）：

| 混淆项 | 为什么致命 | 怎么记 |
|--------|-----------|--------|
| 壳体温度 | 实测 54→60 ℃ 期间同一速度的摩擦力矩漂移 ±0.002 N·m —— 这已经和可能的个体差异同量级 | 每步自动记 `case_c` |
| 供电电压 | 摩擦与限流都随电压变 | 每步自动记 `supply_v`；`compare` 会检查各单元是否一致并警告 |

**背靠背跑两遍时第二遍会更热**，所以第二遍的差是重复性的**上界**（含热漂移），
读的时候要知道这一点。

---

## 二、需要什么

* 硬件：上位机（Jetson 可用）+ 宇树 AT32 单总线转接板 + 12 V 电源 + **一颗** S288
* **一次只接一颗**（总线上重复 ID 会让整条总线异常；单颗时它就是 ID 0）
* **输出轴上什么都不能装**：舵盘、连杆、砝码都会进惯量那一步。空轴、悬空
* 壳体上贴标签。**协议里没有序列号也没有固件版本**，身份只能靠人贴的标签；
  记录里会写明这一点（`how_identified`），不假装它是仪器读出来的
* 时间：一颗约 4 分钟；两遍约 8 分钟

## 三、流程：一条命令，八步

`bam_unit.py run` 依次执行：

| # | 步骤 | 实际命令 | 测什么 | 约耗时 |
|---|------|---------|--------|-------|
| 1 | encoder | `bam_friction.py encoder --id N` | 转子编码器 vs 输出端编码器：零点偏置、跨换向的滞回（M1/M7） | 3 s |
| 2 | friction_sweep | `bam_friction.py sweep --speeds <固定9点>` | 成对（±同速）摩擦曲线，抵消重力与零偏（M6a） | 40 s |
| 3 | breakaway | `bam_friction.py breakaway` | 纯力矩前馈斜坡 → 静摩擦/破断力矩（M4 的静摩擦部分） | 40 s |
| 4 | friction_fit | `bam_fit.py --curve ... --stiction <本颗实测>` | Stribeck 拟合（Fc/Fs/vs/α/Fv）+ 与拟合无关的稳健值 | 5 s |
| 5 | delay | `bam_dynamics.py delay --trials 40` | 传输延迟 + 力矩一阶上升（M2；同时回答 M5 电流环） | 15 s |
| 6 | compliance | `bam_dynamics.py compliance` | 破断以下的双编码器卷绕 → 传动链刚度（M6b） | 15 s |
| 7 | backlash | `bam_dynamics.py backlash` | 同一位置双向逼近 → 回差（M7） | 25 s |
| 8 | inertia | `bam_dynamics.py inertia --vmax 1.5` | 力矩阶跃 → 角加速度 → 关节等效惯量（M6b） | 20 s |

**速度集合固定在 `bam_unit.py` 里**（`0.02,0.04,0.07,0.12,0.2,0.35,0.6,1.0,1.5`
输出端 rad/s，9 点，2 次重复）—— 单元之间只有激励相同才可比。这是产出
`s288_bam.json` 那一套点。

第 4 步把**本颗实测的破断力矩**喂给拟合，第 5/8 步把**本颗实测的摩擦**喂给惯量反演
（`--friction`）—— 用别的单元的摩擦去算这一颗的惯量会直接把系统误差灌进 J。

### 每步的判据（超出范围先怀疑测量，再怀疑舵机）

| 量 | 参考值（S288-01 实测） | 超出多少要警觉 |
|----|----------------------|---------------|
| 编码器间偏置 | ≈ −1.6°（随位置 ±0.4°，含 13 bit 输出编码器非线性） | >2° |
| 回差（跨换向滞回） | 1.06° = 0.0184 rad，重复性 0.014° | >2° 或 <0.3° |
| 卡死平台 F(0.02 rad/s) | 0.0329 N·m | ±0.005 |
| 破断力矩 | 0.0365 N·m（步长 0.005 → 分辨率 ±0.0025） | 超出 0.030–0.045 |
| 动摩擦下凹最低点 | 0.0185 @ v≈0.04 rad/s | 见拟合表 |
| Fc / Fv | 0.0187 / 0.0109 | ±30% |
| command_delay | 0.48 ms（带宽带 0.44–0.51） | >1 ms |
| 力矩上升 τ | 0.54 ms（10–90% 1.19 ms） | >2 ms（手册 M5 的判据线） |
| 传动刚度（输出端） | 第一次测到 ~1600，但**不可复现** | 工具会判 `NOT MEASURED`；别用它做判据 |
| 关节等效惯量 | 5e-4 kg·m²（4–6e-4） | 差一个数量级 = 采集有问题 |

### 失败了怎么办

某一步失败（超时、无结果行、退出码非 0）时：**它会被写进 `steps_failed`，不会被隐藏**，
该项在 `compare` 表里显示 `--`。不要手抄一个数补上 —— 那会让整张对比表失去意义。
先看 `bam_data/units/<label>/logs/<step>.log`。

## 四、产出与读取

```
bam_data/units/<label>/
  record.json                      ← 全部结果 + 上下文 + 工件 sha256
  logs/<step>.log                  ← 每步的完整人读输出
  M6a_friction_curve.csv           ← 本颗的摩擦曲线（原始，未压缩）
  s288_bam_friction_<label>.json   ← 本颗的 m6 风格摩擦参数
  M6a_friction_fit_<label>.png     ← 曲线 + 拟合 + XL330 对比
```

`record.json` 里每个工件都带 `sha256`，`software.git_head` 记录用的是哪版代码 ——
以后可以验证这份记录没被改过、且知道它出自哪一版采集代码。

```bash
python3 bam_unit.py compare        # 跨单元表 + 重复差 + 上下文一致性
```

`compare` 会：
* 列出每个量的**跨单元**值、spread、均值、sd、相对 sd
* 标出 >2sd 的单元（"可疑离群，去看它的日志"）
* 单独列出**同单元重复**的差 → 噪声地板
* 检查各单元的电压/温度/电源是否可比，不一致就警告

**读法**：只有当某个量的跨单元散布**明显大于**它自己的重复差时，才谈得上"个体差异"。

## 五、哪些量**本来就应该每颗都一样**

这一栏是排错用的：如果它们不一样，那说明测错了、或固件不同，**不是个体差异**。

| 量 | 为什么必须一样 |
|----|--------------|
| 减速比 288.35（= 70070/243） | 协议常数 |
| 力矩 LSB：256000 counts = 1 N·m（转子端） | 协议常数 |
| 位置 LSB：32768/2π counts/（转子 rad） | 协议常数 |
| 输出端编码器：13 bit、单圈 | 协议常数 |
| 各限值/编码范围（±32767 等） | 协议常数 |

反过来，**摩擦、破断、延迟、回差、惯量都是机械/热学量，天然会有个体差异** ——
这正是要测的东西。

## 六、诚实清单：这套方法测不到什么

| 项 | 为什么 | 需要什么 |
|----|-------|---------|
| 最大力矩 / 电流限幅（M4） | 要堵转**并且读电流** —— 舵机反馈帧里**没有电流字段**，手册里那张表的"反馈电流(A)"只能来自电源显示 | `bam_unit.py limit`（见下）+ 有电流显示的电源 |
| 电压敏感性（M3） | 只有 12 V 定值电源；母线反馈分辨率 0.5 V，太粗 | 可调电源 |
| 固件版本 | 协议里查不到 | Windows 上位机 |
| 绝对精度 | 没有任何溯源标准件 —— 所有数都是"这一颗在 12 V / 当时的室温下"的表现 | 标准转矩计 |

### M4 限流点：能测，而且不需要砝码

```bash
python3 bam_unit.py limit --id 0 --tmax 0.30 --step 0.02 --current 0.32
```

* **要你做的**：同时按住机身**和输出轴**（或者把轴夹住）。纯力矩前馈从 0 爬到 0.30 N·m，
  每档 0.35 s。**整个斜坡控制在 5 s 内**（手册的过热提醒），堵转对电机不友好
* 舵机反馈会给出力矩**平台**（电流限幅的力矩表现）；**电流那一半必须你从电源显示读**，
  再用 `--current` 传进来，它就能给出 `kt_rotor`
* 注意：手册说"官方 0.32 A 限流"，但**官方 S288 手册（493 行全文）里没有任何力矩/电流指标** ——
  那个 0.32 A 出自你那份《S288 舵机 BAM 建模与动力学分析测试手册》（2026-09-04）M4 节，
  而它没有引用来源。**别把它当官方数据用**；测一次就有自己的数
* 手按住的轴不是刚性的：如果斜坡中轴爬动了，平台值只是**下界**

## 八、这套数怎么进仿真

单元之间会有差异，两个路线：

1. **中位数 + 域随机化**（推荐）：用几颗的中位数当名义参数，把个体差异当作域随机化的一维
   （BAM 本来就是为域随机化设计的）。这样训出来的策略对"换一颗舵机"是鲁棒的。
2. **逐颗标定**：每颗一套参数，部署时按标签选。更准，但每一颗都要跑一遍这套流程。

不要用单颗的极值当名义值 —— 那会把一颗的偏差当成全体。

## 九、实测示例：S288-01 两遍（基线，2026-09-11）

流程本身只跑过一次（同一颗、两遍），但它已经给出了那张最关键的表的形态。
两遍**背靠背**（壳体 61→62 ℃，电源 12.5 V），`compare` 直接给出的重复差：

| 量 | 两遍差 | 判定 |
|----|-------|------|
| command delay | 0.47 vs 0.47 ms（0.0%） | 稳 |
| 力矩上升 τ | 0.54 vs 0.56 ms（3.6%） | 稳 |
| 回差 | 0.01703 vs 0.01672 rad（1.8%） | 稳 |
| 编码器间偏置 | −1.318 vs −1.309°（0.3%） | 稳 |
| 卡死平台 | 0.03275 vs 0.03299 N·m（0.7%） | 稳 |
| 摩擦下凹 | 0.01961 vs 0.01972 N·m（0.6%） | 稳 |
| 破断（stiction） | 0.04 vs 0.04 N·m（步长 0.005 → 分辨率 ±0.0025） | 稳（但分辨率就是判据） |
| Fc / Fs / Fv（拟合） | 2.1% / 2.2% / 4.9% | 这一对还行，但见下 |
| 粘滞斜率（0.4–1.2 rad/s） | 0.00847 vs 0.00737（13.8%） | 弱 |
| 关节等效惯量 | 6.1e-4 vs 7.1e-4 kg·m²（7.4%） | 弱 |

**同一个单元、更早的另一对重复**（壳体更热、跨了 20 分钟）给出的差明显更大：
惯量 26.8%、粘滞斜率 47.3%、Fc/Fs/Fv 11.7%/14.0%/22.2%。

两对重复**对自己的可重复性判断都不一致** —— 这本身就是为什么要先做它：
- **稳定的一档**（延迟、上升时间、回差、编码器偏置、卡死平台、下凹）：两对都在 4% 以内
- **随温度走的一档**（拟合的摩擦分割、惯量）：7%–27%
- **最不可信**：粘滞斜率（14%–47%）、传动刚度（不可测）

**结论用法**：将来拿到 4 颗舵机时，如果某颗的延迟是 0.60 ms（比基线高 25%），那是真实的个体差异；
如果某颗的惯量是 0.7e-4（比基线低 15%），**那不算差异**，得先看它自己的重复差。

另外注意两个 `compare` 自动检查到的点：
- 这一对的 `supply` 是 12.5 V 而上下文里写的是 12.0 V 设定值 —— 记录里存的是**舵机自己报的母线电压**，
  和电源设定值可能差 0.5 V。跨单元比较时看这个字段，不要看设定值。
- 两遍的 `case temp` 相差 1 ℃（61→62），这正是"重复差里含热漂移"的来源。
